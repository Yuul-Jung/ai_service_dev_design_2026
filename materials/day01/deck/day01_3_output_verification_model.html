00같은 요청, 다른 답p.112–115

이 구간은 세 부분입니다. 출력 설정이 무엇을 바꾸는가(p.113–128), 답의 근거를 어떻게 확인하는가(p.129–143), 과제에 맞는 모델을 어떻게 고르는가(p.144–153). 마지막에 AI와 스스로 공부하는 방법(p.154–164)이 붙습니다.

자료 p.113 · 이 구간의 목적

표현의 다양성·출력 길이·추론에 쓰는 자원을 구분해 설정을 고른다.

최댓값 선택 (p.115)

가상 분포 Hello 70% / Hi 30%에서 확률이 가장 높은 Hello를 고른다. 같은 분포면 항상 같은 결과.

샘플링

확률에 따라 하나를 뽑는다. Hello가 더 자주 나오지만 Hi도 선택될 수 있다.

같은 요청에서 Hello!와 Hi!가 번갈아 나오는 이유(p.114)는 모델이 바뀌어서가 아니라, 같은 분포에서 다른 후보가 뽑혔기 때문입니다. 다음 토큰 확률을 계산하는 과정은 오후 첫 구간 p.74–77에서 다뤘습니다.

보충 · 자료 밖 내용

최댓값 선택은 greedy decoding이라고도 부릅니다. 이론적으로는 같은 입력에 같은 답을 내지만, 실제 서비스에서는 온도를 0으로 두어도 답이 조금씩 달라지는 경우가 보고됩니다. 대규모 병렬 계산에서 덧셈 순서가 달라지며 생기는 아주 작은 수치 차이가 후보 순위를 바꿀 수 있기 때문입니다. 완전히 같은 답이 필요한 업무라면 서비스의 재현성 설정과 문서를 확인하세요.

검증 · 온도 T를 적용해 다시 계산 일치

새 확률 ∝ (원래 확률)^(1/T) ← softmax(점수 / T)와 같은 계산 T = 0.5 : 0.9², 0.05², 0.03², 0.02² = 0.81, 0.0025, 0.0009, 0.0004 (합 0.8138) → 99.53%, 0.31%, 0.11%, 0.05% T = 2 : √0.9, √0.05, √0.03, √0.02 = 0.949, 0.224, 0.173, 0.141 (합 1.487) → 63.80%, 15.04%, 11.65%, 9.51%

자료의 여덟 값이 모두 소수 둘째 자리까지 일치합니다. 온도를 낮추면 큰 확률이 더 커지고, 높이면 확률이 고르게 퍼집니다.

자료 p.117

가정: 원문은 금요일, 가장 높은 확률의 후보는 토요일. 온도를 낮추면 높은 확률의 후보에 선택이 더 집중 → 틀린 날짜를 더 반복할 수 있음 → 원문의 날짜와 생성한 날짜를 대조해야 한다.
“온도는 사실을 확인하거나 새 자료를 제공하는 설정이 아니다.”

추가 계산 · 틀린 후보가 1위일 때 온도를 낮추면 추가

가상 분포 토요일 70% / 금요일 30% (강사 역량 p.181의 예) T = 1 → 토요일 70.0% 금요일 30.0% T = 0.5 → 토요일 84.5% 금요일 15.5% T = 0.2 → 토요일 98.6% 금요일 1.4%

온도를 낮출수록 틀린 날짜가 더 확실하게 선택됩니다. p.117의 주장을 숫자로 확인한 결과입니다.

보충 · 자료 밖 내용

온도를 0에 가깝게 두면 사실상 최댓값 선택과 같아집니다. 많은 서비스가 사실 확인형 작업에는 낮은 온도를, 아이디어 발상·문구 후보 생성에는 높은 온도를 권합니다. 다만 그 이유는 “정확해져서”가 아니라 “답이 덜 흔들려서”입니다. 정확성은 입력한 근거와 검증으로 확보합니다.

02후보 제한 · 상위 수와 누적 확률p.118–119

상위 후보 수 · top-k

확률이 높은 순서로 k개만 남긴다. 예: k = 2 → 상위 2개

누적 확률 · top-p

확률이 높은 순서로 더해 p에 도달할 때까지 남긴다. 예: p = 0.9 → 누적 90%까지

후보 (p.119 · 설명용)확률누적top-k = 2top-p = 0.9
가50%50%남김남김
나30%80%남김남김
다15%95%제외남김
라5%100%제외제외

검증 · 남은 후보를 100%로 다시 환산 일치 환산값 추가

top-k = 2 : 가 50/80 = 62.5% 나 30/80 = 37.5% top-p = 0.9: 누적 80% < 90% 이므로 ‘다’까지 포함(누적 95%) 가 50/95 = 52.6% 나 30/95 = 31.6% 다 15/95 = 15.8%

남기는 후보는 자료와 일치합니다. p.118의 “남은 후보의 확률을 합계 100%로 환산한 뒤 선택한다”를 적용한 실제 선택 확률은 자료에 없어 계산해 덧붙였습니다.

보충 · 자료 밖 내용

누적 확률 방식은 Holtzman 등(2020)의 논문 “The Curious Case of Neural Text Degeneration”에서 nucleus sampling이라는 이름으로 제안되었습니다. top-p는 분포 모양에 따라 남는 후보 수가 저절로 달라진다는 점이 top-k와 다릅니다. 확신이 높은 자리에서는 후보가 한두 개만 남고, 여러 표현이 가능한 자리에서는 많이 남습니다. 일부 API 문서는 온도와 top-p를 동시에 크게 바꾸지 말고 하나만 조정하라고 권합니다. 지원하는 설정과 권장 사항은 서비스마다 다릅니다.

보충 · 자료 밖 내용

  • API는 생성이 멈춘 이유를 함께 돌려줍니다. 예를 들어 Anthropic API는 stop_reason 값이 max_tokens일 때, OpenAI API는 finish_reason 값이 length일 때 출력 한도로 멈춘 것입니다. p.121의 “서비스의 종료 정보”가 이것입니다.
  • 문맥 한도 안에 들어갔다고 해서 모든 부분이 똑같이 잘 쓰이는 것은 아닙니다. 긴 입력의 중간에 있는 정보를 덜 활용하는 경향을 보고한 연구도 있습니다(Liu 등, 2023, “Lost in the Middle”). p.122처럼 필요한 조건만 골라 넣는 것은 한도 문제뿐 아니라 답의 품질에도 도움이 됩니다.

  • 왜 생기는가. 사전학습의 목표는 “그럴듯한 다음 토큰”입니다(오후 첫 구간 p.93–97). 근거가 없는 질문에도 모델은 가장 그럴듯한 이어 쓰기를 생성하므로, 형식은 자연스럽지만 내용은 틀린 답이 나올 수 있습니다.
  • 줄이는 방법. 근거 자료를 입력에 넣기, “자료에 없으면 없다고 답하라”고 지시하기, 답의 각 주장마다 근거 문장을 함께 내게 하기, 생성 뒤 원문과 대조하기. 어느 방법도 환각을 0으로 만들지는 못하므로 마지막 대조 단계는 빠질 수 없습니다.
  • 영어권에서는 hallucination 대신 confabulation(작화)이라는 용어를 쓰자는 주장도 있습니다. 사람이 기억의 빈 곳을 그럴듯한 이야기로 채우는 현상에 더 가깝다는 이유입니다.

12핵심 정리

  • 같은 요청에서 다른 답이 나오는 것은 같은 분포에서 다른 후보를 뽑기 때문입니다.
  • 온도·top-k·top-p는 표현의 다양성을, 출력 한도는 길이를, 추론 설정은 답 전의 처리량을 바꿉니다. 어느 것도 사실 여부를 바꾸지 않습니다.
  • 답은 주장을 나누고 원문과 대조해 확인합니다. “미정”과 “자료에 없음”은 다른 답입니다.
