검증 · CAG와 KV 캐시 일치

CAG(Cache-Augmented Generation)의 공식 저장소는 이 접근을 “실시간 검색을 거치지 않고 모든 관련 자료를 모델의 문맥에 미리 넣고 런타임 계산(KV 캐시)을 보관해, 추론할 때 미리 채운 KV 캐시로 곧바로 답한다”고 설명합니다. 이는 슬라이드의 “자료를 읽는 계산을 재사용”과 같고, 저장소는 이점으로 검색 지연의 감소와 검색 오류의 감소를 들면서 동시에 RAG의 문제(검색 지연·검색 오류·시스템 복잡성)를 짚습니다. 다만 캐시가 ‘계산의 재사용’이지 ‘자료를 더 잘 읽는 것’은 아니라는 슬라이드의 단서가 중요합니다. 전체를 넣어도 필요한 내용을 놓칠 수 있다는 위의 경고(p.6)는 7일차 p.119의 “긴 자료를 넣을 수 있다고 모두 잘 쓰는 것은 아니다”와 이어집니다.

03검색 증강 생성(RAG)과 자료 준비·읽기 방식의 선택p.16–19

자료 p.16–19

이 질문에 답하려면 어느 부분을 찾아야 할까? “어떤 데이터를 저장하고 서로 어떻게 연결할지 정하려면 무엇을 검토해야 하나?” 검색 증강 생성(RAG)은 질문으로 검색 → 질문과 찾은 원문을 함께 모델 입력에 전달 → 모델이 제공된 자료를 사용해 답한다. 자료의 준비와 읽기 방식을 함께 고른다: 전체 입력(정해진 범위를 한꺼번에), 조건 조회(알려진 문서·버전·항목을 정확히), RAG(질문으로 후보를 찾고 본문을 제공), 파일 탐색(읽은 내용에 따라 다음 파일·범위를 고름). 자료 준비는 미리, 검색은 질문이 들어온 뒤: 자료를 넣거나 바꿀 때(원문 → 검색할 조각으로 나누고 출처를 붙임 → 검색할 자료 보관), 질문이 들어올 때(사용자 질문 → 관련 부분 찾기 → 본문·출처).

전체 입력짧고 전체 맥락이 필요한 자료입력이 길수록 시간·비용 증가
조건 조회문서·버전·항목이 정해진 경우조건이 저장되어 있어야 함

파일 탐색읽은 내용에 따라 다음을 정해야 하는 경우처리 비용·시간이 큼(p.12)

자료 p.29–32

임베딩: 내용을 비교할 수 있는 숫자로 표현한다. 20쪽의 제목과 본문 → 임베딩 모델 → 숫자 목록(0.0144, −0.0128, −0.0435 …). “이번 모델의 출력은 숫자 384개로 된 벡터다. 이 숫자 개수가 벡터의 차원이다.” (실제 계산 모델: multilingual-e5-small) 임베딩 모델도 자료에서 관계를 학습한다(관련 문장의 벡터는 가깝게, 다른 문장과는 구별되도록). 문서 준비는 ‘제목 + 본문 → 문서 벡터 저장’, 질문 입력은 ‘질문 → 질문 벡터 계산’이며 문서와 질문에 호환되는 모델·입력 규칙을 적용한다. 벡터의 차원이 같아도 바로 비교할 수는 없다. “벡터가 내용을 표현하는 방식은 모델이 학습한 관계에 따라 달라진다.”

검증 · multilingual-e5-small의 규모와, 차원이 같아도 비교할 수 없는 이유 p.29·p.32 확인 추가 실행 512토큰·입력 접두사 미확인

E5 계열의 공식 저장소(microsoft/unilm)의 모델 표는 multilingual-e5-small을 12층, 임베딩 크기 384로 적어 슬라이드의 384차원과 일치합니다. 384 × 4바이트(32비트 실수) = 1,536바이트/벡터이므로 문서 10만 개의 벡터는 약 153.6MB입니다(작성자 계산).

384차원 공간을 시뮬레이션: 문서 벡터 5개, 질문은 3번 문서와 가까움 같은 모델(같은 공간): 가장 가까운 문서 = 3번 · 코사인 유사도 0.952 문서만 다른 모델의 공간으로 바꿈(차원은 그대로 384): 가장 가까운 문서 = 4번 · 최대 유사도 0.058 (0 근처)

두 벡터의 길이(384)가 같아도 서로 다른 모델이 만든 공간에서는 같은 위치가 다른 뜻이라 비교 결과가 무의미합니다(여기서는 서로 다른 표현 공간을 무작위 회전으로 흉내 냄). 그래서 모델을 바꾸면 문서 벡터를 다시 만들어야 한다는 p.32의 단서가 맞습니다. 슬라이드의 “입력 한도는 512토큰”과 “질문·문서의 입력 규칙이 다르다(긴 조각은 끝이 잘릴 수 있다)”는 공식 저장소의 표·본문에서 찾지 못해 확인하지 못했습니다(모델 카드에 있는 정보일 가능성이 있음, 작성자 지식).

코사인 유사도는 벡터의 방향을 비교한다(같은 방향에 가까울수록 점수가 높다). 실제 검색은 384개 숫자를 함께 비교하며 2차원 화살표는 방향 비교를 설명하는 도식이다. 실제 검색 결과(순위 · 조각 · 원문 주제 · 유사도): 1 T22 데이터 모델 설계 질문 0.8896 · 2 T19 데이터 모델의 뜻 0.8871 · 3 T17 서비스 전체 구조 0.8809 · 4 T20 데이터 종류·관계·형태 0.8755. “유사도는 정답 확률이 아니다. 후보의 실제 내용을 읽어야 한다.” 후보 개수와 유사도 기준값은 다른 조건이다(상위 3개 선택 → T22·T19·T17, 0.885 이상만 선택 → 이 결과에서는 2개가 남는다).

검증 · 코사인 유사도의 성질과 후보 선택 조건 (직접 계산) p.33–36 일치

코사인 유사도: 같은 방향(길이만 2배) 1.000 · 직각 0.000 · 반대 방향 −1.000 → 길이가 아니라 방향을 비교 유사도를 내림차순으로 정렬 → T22 > T19 > T17 > T20 (슬라이드의 순위와 같음) 상위 3개 선택 → T22, T19, T17 · 0.885 이상 선택 → T22, T19 (2개) 1위(0.8896)와 4위(0.8755)의 차이 = 0.0141

슬라이드의 “2개가 남는다”가 확인됩니다. 눈여겨볼 점은 1위와 4위의 유사도 차이가 0.014로 매우 작다는 것입니다. 이 차이로 순위를 단정하기 어려우므로 기준값 0.885는 0.8871과 0.8809 사이의 임의의 선이고, 기준값을 0.880으로 낮추면 T17이, 0.875로 낮추면 T20이 들어옵니다. 그래서 점수 자체가 아니라 후보의 실제 내용을 읽고 근거를 정해야 합니다(p.34). 이 0.8896 등의 값은 실제 모델 계산 결과로 제시된 것이며, 이 환경에서는 모델 가중치에 접속할 수 없어 재계산하지 못했습니다.

자료 p.37–41

벡터 색인: 모든 벡터를 비교하지 않고 찾기. 모든 벡터와 비교하는 방식과 가까운 벡터의 연결로 탐색하는 방식. “비교량을 줄여 빠르게 찾는다. 대신 필요한 후보를 놓칠 수 있다.” 원문 보관·검색 정보 관리·모델 처리는 서로 다른 역할이다. 원문을 고치면 검색용 표현도 갱신해야 한다(변경 전 → 변경 처리 중: 본문은 수정, 벡터는 이전 → 준비 완료). 저장 완료와 검색 준비 완료를 구분하고 실패한 갱신을 확인한다. 임베딩 모델은 내 자료와 질문으로 고른다(내 분야 문서를 잘 찾는가? 자료 형태·길이를 처리하는가? 사용 환경·비용이 맞는가? 같은 질문의 검색 결과로 비교).

검증 · 벡터 색인의 성격 (pgvector 공식 문서) p.37 일치

pgvector의 공식 저장소는 “기본적으로 정확한 최근접 이웃 검색을 하며 이는 완벽한 재현율을 준다”, “색인을 더하면 근사 검색을 하며 재현율을 일부 내주고 속도를 얻는다. 색인을 추가한 뒤에는 같은 질의의 결과가 달라질 수 있다”고 설명하고, HNSW 색인은 다층 그래프를 만든다고 밝힙니다. 슬라이드의 “비교량을 줄여 빠르게 찾는다, 대신 필요한 후보를 놓칠 수 있다”와 ‘가까운 벡터의 연결로 탐색’이 같은 설명입니다. 특히 색인을 만든 뒤에는 같은 질문의 결과가 달라질 수 있어, 검색 평가는 색인 설정을 고정한 상태에서 비교해야 합니다.

주의 · 갱신 도중의 판본 불일치 (p.39)

원문은 이미 수정됐는데 벡터는 이전 상태인 구간이 생깁니다. 이때 검색은 새 원문의 내용이 아니라 옛 내용으로 후보를 고를 수 있습니다. 슬라이드의 “저장 완료와 검색 준비 완료를 구분한다”는 이 구간을 가리키며, 삭제한 자료가 검색 대상에서 제외됐는지도 같은 방식으로 확인해야 합니다.

07핵심 정리

  • 자료는 질문에서 거꾸로 준비합니다(질문 → 필요한 정보 → 그 정보가 있는 자료). 전체 입력은 단순하지만 길수록 비용이 커지고, 캐시는 계산의 재사용이지 더 잘 읽는 것이 아닙니다.
  • 조건으로 범위를 정하고 그 안에서 내용으로 찾으며, 파일 탐색은 더 나은 답과 더 큰 처리 비용(질문당 6.3배, 정답당 4.7배)을 함께 봅니다.
  • 청킹은 설명이 걸친 길이보다 겹침이 길어야 경계를 살립니다(겹침 4어절 실패, 8어절 성공). 조각마다 제목·쪽수·출처를 저장합니다.
  • 임베딩은 같은 모델이 만든 벡터끼리만 비교할 수 있고(차원이 같아도 유사도 0.058로 무의미), 유사도는 정답 확률이 아니며 1위와 4위의 차이가 0.014로 작을 수 있습니다.
  • 벡터 색인은 속도를 얻는 대신 후보를 놓칠 수 있고, 원문을 고치면 벡터도 갱신하며 ‘저장 완료’와 ‘검색 준비 완료’를 구별합니다.
