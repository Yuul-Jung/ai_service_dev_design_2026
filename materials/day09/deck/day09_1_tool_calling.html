LangChain은 에이전트를 만들 때 가져다 쓰는 프로그램 기능 묶음이다. model(어떤 모델을 호출할지 지정), tools(모델이 요청할 도구와 실행 함수를 등록), createAgent(...)(모델 호출과 도구 실행을 이어 주는 구성을 만든다), agent.invoke(...)(사용자 메시지를 주고 작업을 시작한다). 공식 날씨 예의 호출 구조에서 함수의 반환은 고정 문자열인 예제이며, 실제 날씨 조회라면 함수 안에서 외부 날씨 서비스를 연결해야 한다.

자료 p.29–36 · 정해진 흐름과 모델의 선택

도구가 여러 개라면 다음 작업은 누가 정할까? 실행할 기능을 갖추는 것과 작업 순서를 정하는 것은 다른 일이다. 미리 연결한 순서대로 처리할 수도 있고(워크플로: 파일 선택 → 파일 읽기 → 내용 설명, 각 처리 단계가 노드), 받은 결과를 보고 AI가 다음 기능을 고를 수도 있다. 필수 순서는 정하고 필요한 판단만 AI에 맡길 수도 있다. Dify의 도구 노드는 도구 선택(이 단계에서 실행할 기능)·인증정보(서비스에 접근할 계정 정보)·도구 입력(직접 넣거나 앞 결과에서 받음)·반환 값(다음 단계에서 사용)을 설정한다. 조건 분기(정한 조건으로 경로를 나눔: 파일이 있는가?)와 모델의 판단(내용을 읽고 근거를 고름: 어떤 문단이 질문에 답하는가?)은 다르다. 질문 받기와 저장은 고정하고 어떤 자료를 읽을지는 AI가 고르게 할 수 있다. 경로와 조건을 미리 정할 수 있으면 고정된 흐름으로, 다음 행동을 미리 정하기 어려우면 모델이 고르게 하며, 필요한 유연성과 호출 시간·비용을 비교한다.

어떤 값을 돌려줘야 모델이 다음 행동을 고를 수 있는가?읽은 본문과 출처, 저장 위치와 처리 결과, 실패한 대상과 이유처럼 다음 행동에 필요한 정보
모델·도구·하네스는 각각 무엇을 맡는가?모델은 요청을 만들고, 도구는 실제 작업을 처리하며, 하네스는 입력 구성·모델 호출·도구 실행·결과 재입력을 이어 준다
저장한 파일·기록과 현재 모델 입력은 어떻게 다른가?파일·기록은 저장된 자료이고, 현재 입력은 이번 응답에 쓰도록 구성해 전달한 정보다. 읽어서 전달해야 입력이 된다
정한 경로와 모델의 선택을 어떻게 함께 쓰는가?필수 순서는 고정하고 필요한 판단(읽을 자료 고르기)만 모델에 맡기며 호출 시간·비용을 비교한다

06핵심 정리

  • 모델은 기능 이름과 입력 값을 요청하고, 프로그램(도구)이 실제로 실행해 반환합니다. 도구 정의(사용법)·도구 호출(이번 값)·도구 반환(결과)은 서로 다른 것입니다.
  • 파일 이름은 내용이 아니고, 대화창의 글은 저장된 파일이 아니며, 저장 결과는 파일을 열어 확인합니다.
  • 지침(“이 폴더만 써라”)은 모델이 참고할 조건이고, 실행 환경의 접근 제한이 실제로 막습니다.
  • 에이전트는 모델과 도구의 반복이고 하네스가 그 반복을 이어 줍니다. 정해진 흐름과 모델의 선택은 필요한 유연성과 시간·비용으로 고르고 함께 쓸 수 있습니다.
  • 프로그램이 필요한 결과만 골라 전달하면 모델이 읽는 양이 크게 줄지만(예: 약 620배, 근사), 선별 규칙의 오류는 모델이 볼 수 없습니다.
