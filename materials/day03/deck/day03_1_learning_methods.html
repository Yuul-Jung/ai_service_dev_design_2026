검증 · 숫자 코드를 회귀로 풀면 생기는 일 (추가 계산) 자료의 주장 확인

결제 = 1, 계정 = 2 로 두고 숫자를 예측(회귀)했을 때 예측값 1.5 → “결제와 계정 사이의 부서”는 없다 → 의미가 없음 예측값 1.2와 1.8의 차이 0.6 → 부서 사이의 거리가 아님 처리시간 2.5시간 → 2시간과 3시간 사이의 실제 시간 → 의미가 있음 예측 2시간, 실제 2.5시간이면 0.5시간 빗나갔다고 말할 수 있음

숫자로 적었다는 사실이 아니라 숫자의 크기와 차이가 의미를 갖는가가 기준입니다. p.52의 질문 “숫자로 된 범주도 회귀인가?”의 답은 “아니다”입니다.

보충 · 경계에 있는 경우 · 순서가 있는 범주

별점 1~5처럼 순서는 있지만 간격이 같다고 보기 어려운 값은 분류로도, 회귀로도 다룹니다. 판단 기준은 두 가지입니다. ① 틀렸는지 여부만 볼 것인가, 얼마나 빗나갔는지(별 4개를 5개로 예측한 것과 1개로 예측한 것의 차이)까지 볼 것인가. ② 숫자 사이의 간격에 의미를 두어도 되는가. 범주를 숫자 코드로 줄 때는 보통 코드 크기에 의미가 없도록 범주마다 따로 켜고 끄는 표현(원-핫)을 쓰는 것으로 알고 있습니다(작성자 지식).

군집 결과에 이름을 붙이는 일은 별도다. 묶음 A는 “영수증·중복 결제 → 결제 문제”, 묶음 B는 “비밀번호·인증 메일 → 계정 문제”로 묶인 자료를 보고 의미를 붙인 것이며 정답 부서를 맞힌 것이 아니다. 군집은 표현·유사도 기준에 따라 달라지며, 원하는 부서 구분과 일치하지 않을 수 있다.

검증 · “요청 부분의 손실은 제외”가 무엇을 바꾸는가 (추가 계산) 계산 확인

어절로 단순화한 예 요청 6어절 (조건 · 손실 계산에서 제외) 답변 15어절 (학습 대상 · 손실 계산에 포함) 전체 21어절 → 손실에 들어가는 부분은 15 ÷ 21 ≈ 71.4%

이 계산은 어절 단순화이고 실제는 토큰 단위입니다. 요점은 “요청도 입력으로는 쓰이지만, 모델이 따라 말하도록 학습하는 대상은 답변”이라는 것입니다. 1일차 p.98의 “요청·응답 쌍으로 매개변수를 추가 조정”을 더 정확하게 말한 것입니다.

검증 · “요청 손실 제외”는 표준 옵션, 라마 3 문구는 미확인 방식 확인 출처 문구 미확인

요청 부분의 손실을 빼고 답변에만 손실을 계산하는 방식이 실제로 쓰이는 표준 옵션임은 확인했습니다. 지도 미세조정 라이브러리 TRL의 설정 문서에 completion_only_loss가 있고, 요청+완성 형식의 자료에서는 기본으로 완성 부분에만 손실을 계산하며, 값을 False로 두면 전체 시퀀스에 손실을 계산합니다(소스 확인). 즉 구성에 따라 다릅니다. 다만 자료의 “라마 3의 방식에 따라”라는 출처 문구가 논문에 그대로 있는지는 논문 원문을 열 수 없어 확인하지 못했습니다(작성자 기억은 Llama 3 논문 2024가 요청 토큰의 손실을 가린다는 것). 수업에서는 “답변 부분을 학습 대상으로 삼는 것이 일반적이고, 정확한 구성은 쓰는 도구의 설정에서 확인한다”고 말하세요.

1일차 p.99의 “대화창에 예시를 제공하는 것”과 “예시로 추가 학습하는 것”의 차이가 여기서 다시 중요해집니다. 같은 요청과 시범 답변이라도 입력에 넣으면 이번 답변만 바뀌고, 학습 자료로 쓰면 매개변수가 바뀝니다.

보충 · 자료 밖 내용

  • 한 번에 하나가 아니라 여러 개를 비교한다. 같은 문제에 여러 응답을 만들어 보상을 비교하고, 평균보다 보상이 높았던 응답의 생성 방식을 강화하는 방법(그룹 상대 정책 최적화, GRPO)이 있습니다. TRL 라이브러리에 이 방법의 트레이너(GRPOTrainer)가 제공되는 것은 소스에서 확인했고, 수학·코드 문제에 쓰인다는 설명은 논문 원문을 열 수 없어 작성자 지식으로 둡니다. 위 표의 A와 B를 비교하는 구조가 그 단순화입니다.
  • 보상은 확인할 수 있는 과제에서 쓰기 쉽다. 수학 정답이나 코드의 테스트 통과처럼 맞고 틀림을 확인할 수 있으면 보상이 명확합니다. 글쓰기처럼 좋고 나쁨이 주관적인 과제는 사람의 선호를 이용한 보상(08절)이 필요합니다.

주의 · 보상은 설계한 만큼만 평가한다

보상을 잘못 설계하면 모델이 보상을 높이는 편법을 배울 수 있다는 보고가 많습니다(작성자 지식). 예를 들어 “답이 길수록 높은 점수”라는 보상은 쓸데없이 긴 답을 낳습니다. 이 문장은 오후의 “점수가 높다고 목적에 맞는 것은 아니다”(평가지표)와 같은 이야기라서, 오전에 미리 던져 두기 좋습니다.

R1이 이후 강화학습과 추가 지도 미세조정을 번갈아 쓴다는 세부는 논문 본문을 열 수 없어 작성자 지식으로 둡니다. 따라서 위 표의 두 열은 개념을 가르기 위한 단순한 대비이고, “R1은 한쪽만 썼다”는 뜻이 아닙니다. 수업에서 이 사례를 인용하면 학습자가 하나의 방법으로 외우지 않도록 두 방법이 섞인다고 덧붙이세요.

중간 표현은 “앞 층이 계산해 다음 층에 넘기는 값들”이고, 딥러닝은 “여러 층의 표현 변환을 학습하는 방법”입니다(p.38). 1일차 p.34–36에서 처음 나온 구조입니다. 가중치는 입력에 곱하는 계수, 편향은 합에 더하는 값이며, 이 값을 조정하면 같은 입력의 계산 결과도 달라집니다(p.39).

왜 비선형 변환이 필요한가 (p.40)

자료 p.40

곱하고 더하기만 반복하면 여러 층도 하나의 직선 관계로 합칠 수 있다. ReLU(음수는 0, 양수는 그대로)처럼 비선형 변환을 함께 쓰면 하나의 직선으로 나타낼 수 없는 패턴을 표현할 수 있다.

검증 · 층을 쌓아도 직선이라는 말을 숫자로 확인 (추가 계산) 자료의 주장 확인

입력 x = [1, −2] 1층 W1 = [[1, 1], [1, −1]] → h = W1·x = [−1, 3] 2층 W2 = [1, 1] → y = W2·h = 2 두 층을 하나로 합치면 W2·W1 = [2, 0] → y = 2·1 + 0·(−2) = 2 (같음 ✓) 중간에 ReLU를 넣으면 h = [0, 3] → y = 3 (달라짐)

선형 층만 쌓으면 한 층으로 합쳐져서 층을 늘린 의미가 없고, 사이에 비선형 변환이 들어가야 층마다 다른 일을 할 수 있습니다. 이 한 줄이 p.50 질문 “여러 계산층을 쓰는 이유”와 2일차 보충의 답입니다.

ReLU(x) + ReLU(−x) = |x| x = −2, 0, 2 → 2, 0, 2 직선 f(x) = ax + b 로 세 점 (−2, 2), (0, 0), (2, 2)를 지나게 할 수 있을까? f(0) = 0 이므로 b = 0, f(2) = 2 이므로 a = 1 → f(−2) = −2 ≠ 2 → 불가능

ReLU 두 개로 만든 |x|는 직선 하나로는 표현할 수 없는 모양입니다. 자료의 “직선 하나로 표현할 수 없는 관계”의 가장 작은 예입니다.

주의 · 엄밀히 말하면 ‘직선’은 편향이 있는 직선

편향이 있으면 선형 층의 합성은 원점을 지나지 않는 직선(수학에서는 아핀 변환)이 됩니다. p.40의 왼쪽 그림도 원점을 지나지 않는 선입니다. 수업에서는 “직선 하나로 합쳐진다”로 충분하지만, 학습자가 “편향이 있으면 비선형 아닌가요?”라고 물으면 위 설명으로 답하세요.

13핵심 정리

  • 학습 방법(어떤 정보로 배우는가)과 계산 구조(어떻게 계산하는가)와 평가(새 자료에서 얼마나 잘하는가)는 서로 다른 세 질문입니다.
  • 지도학습은 입력과 목표값의 관계, 비지도학습은 정답 없이 구조, 자기지도학습은 자료 자체에서 만든 목표, 강화학습은 행동의 결과를 평가한 보상으로 배웁니다.
  • LLM은 사전학습(자기지도) → 지도 미세조정(시범 답) → 선호·보상 반영으로 배우고, 같은 Transformer 구조에서 학습 자료와 목표만 바뀝니다.
  • 대화에서 고쳐 주는 것은 문맥이고, 모델이 학습하려면 별도의 학습 절차로 매개변수를 조정해야 합니다.
  • 층을 쌓아도 비선형 변환이 없으면 한 층과 같고, 학습은 순전파 → 역전파 → 최적화 순으로 가중치를 바꿉니다.
