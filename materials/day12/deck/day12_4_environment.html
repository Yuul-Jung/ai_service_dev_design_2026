00환경 차이가 학습 참여를 막지 않도록p.72–73

같은 활동을 할 수 있게 준비하되, 사용만 하는 사람에게는 접속과 자료를, 직접 고칠 사람에게는 프로젝트와 실행 조건을 줍니다(p.73).

01공통 조건·계정·실행 장소 고르기p.74–79

자료 p.74–75

수업 전에 맞출 공통 조건은 접근(주소·계정·역할별 권한), 실행(기기·브라우저·프로그램과 버전), 자료(데이터·시작 파일·제출 위치)입니다. 계정과 권한은 누가 시작하고, 누가 무엇을 보며, 수업 후에도 볼 수 있는지를 정합니다.

사용 환경(브라우저로 질문·작업·피드백)과 제작 환경(AI 코딩 도구와 프로젝트에서 기능·설정·배포)은 구별합니다(p.76). 실행 장소는 학습자가 할 조작과 필요한 연산·자료 접근으로 고르고, 설명·코드·결과를 한 문서에서 다루면 클라우드 노트북, 설치 차이를 줄이려면 컨테이너를 고려합니다(p.77–79). 컨테이너도 계정·권한·외부 연결·데이터까지 해결해 주지는 않습니다.

02무엇을 바꿨는지 알아야 결과 차이를 설명한다p.80–82

실행 조건의 버전과 설명·자료의 버전을 함께 관리합니다(p.80). AI로 환경 준비를 자동화할 때는 프로젝트를 읽고 → 점검·설치 도구와 안내를 만들고 → 실제로 자료를 열어 첫 작업을 해 봅니다(p.81). AI가 바꾼 설정은 강사가 이해해야 하고, 누가 무엇을 준비할지는 기관과 맞춥니다(p.82).

04핵심 정리

  • 사용만 할 사람과 직접 고칠 사람에게 줄 것을 나누고, 배울 내용과 무관한 준비 부담은 줄입니다.
  • 수업 전에 접근·실행·자료의 공통 조건과 계정·공개 범위·수업 후 접근을 정합니다.
  • 실행 조건과 설명·자료의 버전을 함께 기록해야 결과 차이를 설명할 수 있고, AI가 바꾼 설정은 강사가 이해해야 합니다.
  • 배포한 도구는 학습자 권한으로 처음부터 도움 요청까지 써 보고, 멈추는 곳마다 원인별 복구 안내를 둡니다.
  • 한도·장애에도 입력과 작업을 보존해 다시 시도할 기회를 남깁니다.
