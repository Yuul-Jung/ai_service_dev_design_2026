주의 · API 키는 비밀번호와 같다

p.55: “비밀번호와 비밀 키는 질문문·공유 자료에 넣지 않는다.” AI에게 코드를 보여 주며 도움을 받을 때도 키 부분은 지우고 보내세요.

보충 · 자료 밖 내용

  • 키는 코드에 직접 쓰지 않고 환경 변수나 비밀 관리 기능에 둡니다. 코드를 공개 저장소에 올리면 키가 그대로 노출되기 때문입니다.
  • 웹 페이지의 자바스크립트처럼 사용자의 브라우저에서 실행되는 코드에 키를 넣으면, 누구나 페이지 소스에서 키를 볼 수 있습니다. 키는 서버 쪽 프로그램에서만 씁니다.
  • 키가 노출되었다면 바로 폐기하고 새로 발급합니다. 지운 커밋에도 기록이 남을 수 있으므로, 저장소에서 지우는 것만으로는 충분하지 않습니다.

첫 응답까지 (p.63)

요청 후 첫 내용이 보일 때까지. 기다림을 느끼는 방식에 영향.

완료까지

전체 응답이 끝날 때까지. 완성 결과를 쓰기까지 걸린 시간.

두 방식의 완료 시각은 같고, 다른 것은 언제부터 보이는가입니다. 스트리밍은 1일차 p.76의 “토큰을 하나씩 골라 이어 붙이는 생성”을 그대로 화면에 흘려보내는 방식이라 가능합니다.

주의

결과 전체를 받아 표나 파일로 저장해야 하는 프로그램이라면, 스트리밍으로 받아도 완료 시간은 줄지 않습니다. 수업 중 학습자가 “스트리밍이 더 빠르다”고 말하면 어느 시간을 말하는지 되물어 주세요.

한도 초과: 제한의 종류와 현재 이용량을 확인한다. 서비스 장애: 상태와 공식 재시도 안내를 확인한다. “같은 요청을 계속 반복하기 전에 오류 메시지를 읽는다.”

보충 · 자료 밖 내용

한도 초과나 일시 장애로 다시 시도할 때는 보통 간격을 점점 늘리며 재시도합니다(지수 백오프, exponential backoff: 1초, 2초, 4초…). 실패하자마자 같은 요청을 반복하면 한도를 더 빨리 소진하고, 장애 중인 서비스에 부담을 더합니다. 권한 오류나 형식 오류는 기다려도 해결되지 않으므로 재시도 대상이 아닙니다.

12핵심 정리

  • API 요청에는 모델·입력·생성 설정·주소·인증이 담기고, 응답에는 문장·종료 이유·사용량이 돌아옵니다.

  • 스트리밍은 첫 응답 시간을 줄일 뿐 완료 시간은 그대로입니다.
