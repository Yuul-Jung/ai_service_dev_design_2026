02한 번의 비용을 수업 전체로p.112–113

자료 p.112 · 교육용 조건

가정: 20명이 각 10회 실행. 앞서 계산한 후보 가 사용(입력 100만 토큰당 1,000원, 출력 100만 토큰당 4,000원).

검증 · 수업 규모의 예상 비용 (p.112–113) 일치

요청 수 20명 × 10회 = 200회 입력 200회 × 1,000토큰 = 200,000토큰 출력 200회 × 200토큰 = 40,000토큰 입력 비용 200,000 ÷ 1,000,000 × 1,000원 = 200원 출력 비용 40,000 ÷ 1,000,000 × 4,000원 = 160원 총비용 200원 + 160원 = 360원 (교차 확인) 한 번 1.8원(p.75) × 200회 = 360원

두 방법의 결과가 같습니다. 후보 나(4.4원)를 썼다면 880원입니다(추가 계산).

보충 · 실제 수업에서 더 넣을 것

실제로는 학습자가 같은 요청을 고쳐 다시 보내고, 대화가 길어지면 앞의 대화가 매번 입력에 다시 들어갑니다(1일차 p.79–81). 그래서 회당 입력 토큰이 처음보다 커지는 경우가 많습니다. 예산을 잡을 때는 횟수와 입력 길이에 여유를 두고, 실제 사용량은 수업 뒤 응답의 사용량 기록이나 콘솔에서 확인하세요.

03총비용과 동시 사용 한도p.114

총비용 (p.114)

20명 × 10회 = 200회. 얼마나 사용하는가.

동시 요청 조건

프로젝트 한도가 분당 10회라면, 20명이 한 번씩 동시에 시작할 때 제한될 수 있음. 한도의 적용 단위도 확인.

추가 계산 · 한도가 수업 시간에 미치는 영향 추가

동시 시작: 20명이 같은 1분 안에 요청 → 10회만 처리, 10회는 제한 전체 실습: 200회 ÷ 분당 10회 = 최소 20분 (요청이 고르게 나뉠 때)

비용은 360원에 불과해도, 이 한도라면 200회 실습에 최소 20분이 필요합니다. 학습자가 몰려서 요청하면 실패와 재시도가 겹쳐 더 길어집니다. 수업 설계에서는 비용보다 이 한도가 더 큰 제약이 될 수 있습니다. 시작 시각을 조 단위로 나누거나, 한 번에 하나만 요청하도록 안내하는 이유입니다.

오후 첫 구간 p.56의 원칙(“프로젝트별 한도라면 키를 나눠도 함께 계산한다”)이 여기서 쓰입니다. 학습자마다 키를 나눠 줘도 같은 프로젝트라면 한도는 하나입니다.

주의 · 알림은 멈추지 않는다 보충

비용 알림과 차단을 혼동하기 쉽습니다. 작성자가 알고 있는 Google Cloud의 예산 기능은, 예산을 넘으면 알림을 보낼 뿐 기본적으로 사용을 멈추지 않습니다. 실제로 멈추려면 별도의 차단 설정이나 자동화가 필요합니다. 다른 서비스도 비슷한 경우가 많으니, “알림을 설정했으니 예산을 넘지 않는다”고 안내하지 않도록 사용할 서비스의 문서를 확인하세요.

표시 예 (p.117 · Gemini API)먼저 확인할 내용대응
403 PERMISSION_DENIED키·프로젝트·모델의 접근 권한권한과 설정을 확인
429 RESOURCE_EXHAUSTED어떤 할당량·요청 한도인가한도 확인 후 간격·사용량 조정
503 UNAVAILABLE제공자 상태·일시 장애 안내안내에 따라 대기·재시도

검증 공식 정의로 확인

세 코드와 이름의 짝은 Google의 공식 오류 코드 정의(googleapis 저장소의 google/rpc/code.proto)와 같습니다. 이 정의에서 PERMISSION_DENIED는 HTTP 403, RESOURCE_EXHAUSTED는 429, UNAVAILABLE은 503에 대응하고, 아래 보충의 INVALID_ARGUMENT(400), NOT_FOUND(404), INTERNAL(500), DEADLINE_EXCEEDED(504)도 같은 파일에서 확인했습니다. Gemini API가 이 코드 체계를 따른다는 것은 작성자 지식입니다. 자료의 단서 “같은 숫자라도 반환된 상세 메시지를 함께 읽는다”도 맞습니다. 예를 들어 429는 분당 요청 수 한도와 일일 한도 등 여러 원인에 같이 쓰입니다.

보충 · 수업에서 만날 수 있는 다른 코드

표시 예흔한 원인재시도로 해결되는가
400 INVALID_ARGUMENT요청 형식·필드 이름·값이 잘못됨 (p.64 “요청 항목이 잘못됐다”)아니요. 요청을 고친다
404 NOT_FOUND모델 이름 오타, 없어졌거나 접근할 수 없는 모델아니요. 모델 이름을 확인한다
500 INTERNAL제공자 쪽 내부 오류. 입력이 지나치게 길 때도 나타날 수 있음잠시 뒤 재시도, 반복되면 입력을 줄인다
504 DEADLINE_EXCEEDED처리 시간이 제한을 넘음입력이나 요청량을 줄여 재시도

목록의 코드와 이름은 위의 공식 정의로 확인했습니다. 서비스에서 나타나는 구체적인 원인은 공식 오류 안내에서 확인하세요. 오후 첫 구간 05절의 원칙대로, 권한·형식 오류는 기다려도 풀리지 않고 한도·장애는 간격을 두고 재시도합니다.

조직 안에서 모델을 실행해도 외부 검색 도구를 쓴다면, “자료가 모두 내부에만 남는다”고 안내할 수 있을까?

먼저 답해 본 뒤 펼치기

안내할 수 없습니다. 모델은 조직 안에서 계산되더라도, 검색 도구에는 검색어가 전달됩니다. 검색어는 보통 질문이나 자료의 일부로 만들어지므로, 내부 자료의 내용이 외부 검색 서비스로 나갈 수 있습니다. 오후 둘째 구간 p.99의 “내부 모델도 외부 검색 도구를 연결하면 정보를 밖으로 보낼 수 있다”가 근거입니다.

정확한 안내는 이렇게 씁니다. “모델은 조직 내부에서 실행됩니다. 단, 검색 기능을 쓰면 검색어가 외부 검색 서비스로 전송됩니다. 내부 자료는 검색 기능을 끈 상태에서만 사용하세요.”

p.123은 다음 시간을 이렇게 예고합니다. “다음에는 모델이 자료에서 배우는 과정과 처음 보는 자료에서 성능을 확인하는 방법을 배운다.”

09핵심 정리

  • 내 계정에서 되는 것과 수업에서 여러 사람이 쓰는 것은 접속·키·비용·한도가 다릅니다.
  • 수업 비용은 인원 × 횟수 × 회당 사용량 × 단가로 어림하고, 실제 사용량으로 다시 확인합니다.
  • 비용이 작아도 분당 한도가 수업 시간을 정할 수 있습니다.
  • 비용 알림은 차단이 아닙니다. 오류는 코드와 상세 메시지를 함께 읽습니다.
  • 안내에 적은 모든 문장은 내가 설명할 수 있어야 하고, 모르는 조건은 확인할 질문으로 남깁니다.
