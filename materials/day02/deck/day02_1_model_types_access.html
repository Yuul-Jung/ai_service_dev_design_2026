보충 · 자료 밖 내용 용어

“공개 가중치(open weights)”와 “오픈소스”는 같은 말이 아닙니다. 오픈소스 이니셔티브(OSI)가 2024년에 발표한 오픈소스 AI 정의는 가중치뿐 아니라 학습 코드와 학습 자료에 관한 충분한 정보까지 공개되어야 오픈소스 AI로 봅니다. 그래서 가중치만 공개한 모델은 흔히 “공개 가중치 모델”로 따로 부릅니다. 수업에서는 학습자가 “오픈소스니까 마음대로 써도 된다”고 말할 때 이 구분과 라이선스 확인을 함께 짚어 주세요.

05규모 · 비트 · 메모리 · 양자화p.18–21

자료 p.18–19

1B는 약 10억 개다. 저장량은 수치의 개수와 값 하나를 표현하는 비트 수에 따라 달라진다. 8비트는 1바이트, 16비트는 2바이트다. 다음 계산에서는 1GB를 10억 바이트로 둔다.

16비트: 10억 개 × 2바이트 = 20억 바이트 = 약 2GB 8비트: 10억 개 × 1바이트 = 10억 바이트 = 약 1GB 4비트: 10억 개 × 0.5바이트 = 약 0.5GB (추가)
양자화 예 (p.21 · 원리용 단순 예)0.120.480.91
표현 가능한 값이 0.00 / 0.50 / 1.00뿐일 때0.000.501.00

검증 · 가장 가까운 값으로 대응 일치

0.12는 0.00까지 0.12, 0.50까지 0.38이므로 0.00으로 갑니다. 0.48은 0.50, 0.91은 1.00이 가장 가깝습니다. 자료의 대응과 같습니다. 표현할 수 있는 값이 적을수록 원래 수치와의 차이가 커질 수 있습니다.

검증 · 실제 모델의 공식 측정값과 대조 계산과 부합 자료 추가

Qwen2.5 공식 저장소의 속도 벤치마크 문서(docs/source/benchmark/speed_benchmark.rst, 2025-01-12 판)에는 Qwen2.5-0.5B-Instruct를 A100 GPU 1장, Transformers로 실행하며 2,048토큰을 생성했을 때의 GPU 메모리가 기록되어 있습니다.

입력 길이BF16 (16비트)GPTQ-Int8GPTQ-Int4
1토큰0.97GB0.64GB0.48GB
6,144토큰1.23GB0.90GB0.73GB

  • 계산과 부합: 0.49B × 2바이트 = 약 0.98GB. 입력이 거의 없을 때 측정된 0.97GB와 거의 같습니다. p.20의 계산 방식이 실제와 맞습니다.
  • 양자화가 정확히 절반이 되지는 않음: 8비트로 바꿔도 0.98GB의 절반(0.49GB)이 아니라 0.64GB입니다. 일부 값은 원래 정밀도로 남기고, 실행에 필요한 메모리가 따로 들기 때문입니다.
  • 입력이 길수록 메모리가 늘어남: 같은 모델도 입력 30,720토큰에서는 2.34GB가 필요했습니다. 문맥을 계산하는 동안 쌓이는 중간 값 때문입니다. p.8의 “계산 중인 데이터”가 이것입니다.
  • 적게 쓴다고 항상 빨라지지는 않음: 같은 표에서 생성 속도는 BF16이 초당 47.40토큰, GPTQ-Int8이 35.17토큰으로 8비트가 더 느렸습니다. 양자화는 메모리를 줄이지만, 속도는 실행 프로그램과 장치에 따라 달라집니다.

주의 · GB의 두 가지 뜻

자료는 1GB를 10억 바이트로 둡니다. 운영체제나 일부 도구는 1GB를 2³⁰ = 1,073,741,824바이트(정확히는 GiB)로 표시해서, 같은 파일이 약 7% 작은 숫자로 보일 수 있습니다. 학습자가 “계산과 다르다”고 하면 단위부터 확인하세요.

계열 소개의 128K는 큰 모델 기준이고, 0.5B의 개별 카드는 32,768토큰입니다. 생성 상한 8K는 양쪽이 같습니다. p.25가 “개별 모델 소개 부분”을 읽으라고 강조하는 이유가 이 차이입니다.

문맥 길이 (p.27)

입력과 이어지는 생성을 처리하는 범위. 입력이 길수록 남는 생성 여유가 줄어드는 제한 방식이 있다.

생성 길이

한 번에 생성할 수 있는 출력의 상한. 문맥에 여유가 있어도 생성 상한을 넘겨 출력할 수는 없다.

1일차 p.120(문맥 한도와 출력 한도)의 가상 모델 설명을 실제 모델 카드에서 확인하는 페이지입니다.

주의 · 카드도 판본이 있다

자료는 “2026-11-03 확인”, “최신 추천 순위가 아님”이라고 밝혔습니다. 모델 카드는 수정될 수 있으므로, 수업 자료에 옮길 때는 확인한 날짜와 판본 이름(예: -Instruct, 기본 모델)을 함께 적습니다.

보충 · 자료 밖 내용

  • MMLU는 Hendrycks 등(2021, ICLR)이 제안한 평가로, 57개 과제의 객관식 문제로 이루어져 있습니다(p.45와 일치).
  • 5-shot은 문제 앞에 풀이 예시 다섯 개를 입력으로 넣는 설정입니다. 1일차 p.99의 “입력에 예시 제공하기”와 같은 방식이라, 설정이 다르면(0-shot 등) 같은 모델도 점수가 달라집니다.
  • 점수를 읽을 때 주의할 점: 시험 문제가 학습 자료에 섞여 들어가면 점수가 실제 능력보다 높게 나올 수 있습니다(오염, contamination). 상위 모델들의 점수가 모여 차이가 잘 드러나지 않는 포화 문제도 있습니다. MMLU 문항 일부에 정답 오류가 있다는 분석(예: MMLU-Redux)과, 더 어려운 변형(예: MMLU-Pro)도 나와 있습니다.

그래서 p.48의 결론처럼, 공개 점수는 후보를 좁히는 데 쓰고, 최종 선택은 내 자료로 직접 시험한 결과로 합니다.

12핵심 정리

  • 모델을 쓰려면 가중치 + 실행 프로그램 + 컴퓨터가 필요하고, 내려받기와 실행은 다른 일입니다.
  • 공개 여부, 실행 주체, 이용 통로, 허용 용도는 서로 다른 질문입니다. 같은 계열 모델도 라이선스가 다를 수 있습니다.
  • 저장량은 수치 개수 × 값 하나의 바이트 수로 어림할 수 있고, 실제 메모리는 입력 길이에 따라 더 늘어납니다.
  • 모델 카드는 개별 판본의 값을 읽고, 벤치마크 점수는 과제·설정·판본과 함께 읽습니다.
  • 모델의 제안과 설명은 실행의 증거가 아닙니다. 실행은 도구 기록으로 확인합니다.
