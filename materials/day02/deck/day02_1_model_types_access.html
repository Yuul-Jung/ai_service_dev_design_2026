강의에서 덧붙인 말 강의

강사는 첫머리에서 “새로운 모델이 나올 때마다 계속 공부해야 한다”고 강조했습니다. 어떤 모델이 무엇에 강하고 약한지에 대한 감각을 예민하게 키우는 것이 목표이고, 그 출발점이 모델 카드에서 정보를 찾는 일입니다(07절).

전날 내용의 복습으로는 ‘규칙 기반 전문가 시스템 → 머신러닝 → 딥러닝·인공신경망 → LLM’의 흐름, ‘모델은 사고하는 뇌를 가상으로 만든 덩어리이며 모델만으로는 아무것도 못 한다’, 입력이 토큰화되어 계산층을 거쳐 다음 토큰을 순서대로 만든다는 과정, 온도(낮추면 확신하는 답, 높이면 다양한 답), 매개변수, 답변 전에 생각 토큰을 먼저 만드는 추론을 짚었습니다. 1일차 자료의 p.24, p.59, p.74–77, p.116, p.123에 해당합니다.

또 지금 쓰는 채팅 앱은 AI 회사가 만든 서비스의 일부일 뿐이라고 했습니다. AI를 제대로 쓰려면 모델을 고르고 접속하는 방법(API·로컬 실행)과 비용·운영을 알아야 한다는 것이 오늘의 출발점입니다.

※ 강의 음성은 AI가 자동으로 받아 적은 글이라 모델명·숫자에 인식 오류가 많습니다. 뜻이 분명한 내용만 옮겼고, 모델명과 수치는 단정하지 않았습니다.

보충 · 자료 밖 내용

공개 가중치를 내 컴퓨터에서 실행할 때 쓰는 실행 프로그램으로는 Ollama, llama.cpp, vLLM, Hugging Face Transformers 등이 널리 알려져 있습니다. 같은 가중치라도 어떤 실행 프로그램과 장치를 쓰느냐에 따라 속도와 필요한 메모리가 달라집니다. 05절에서 공식 측정값으로 확인합니다.

강의에서 덧붙인 말 · 가중치와 실행 환경 강의

강사는 매개변수를 “입력이 들어올 때 어떻게 연산할지에 대한 수많은 계산 값”으로 풀고, 그것을 모두 모은 모델 전체의 수치 데이터를 가중치 데이터라고 했습니다. 공개 모델이라면 “모델을 쓴다 = 가중치 데이터를 내려받는다”고 볼 수 있다고 했습니다.

실행에는 가중치(숫자 덩어리)와 이를 읽어 계산하는 프로그램이 필요하고, 램은 가중치를 올려 두는 공간, GPU는 계산하는 장치입니다. CPU로도 계산은 되지만 그동안 컴퓨터가 멈춘 듯 느려져서, 웬만하면 GPU가 있는 편이 낫다고 했습니다. 직접 돌려 본 과정은 06절에 정리했습니다.

강의에서 덧붙인 말 · “가중치를 직접 고쳤다”는 기사 강의

강사는 오후 수업을 열며 최근 기사를 하나 소개했습니다. 한 AI 회사가 자사 모델을 이용해 아주 작은 공개 모델(0.8B급)의 매개변수를 읽고 가중치를 직접 고쳐서 문제 풀이 점수를 크게 올렸다는 내용입니다. 강사의 요점은 “매개변수는 학습하면서 자동으로 만들어지는 것이라 사람이 읽고 이해해 직접 고치는 것은 거의 불가능에 가깝다”이고, 이 기사는 모델이 작아서 가능했던 예외로 소개한 것입니다. 사람의 뇌에서 뉴런을 하나하나 분석하기는 불가능하지만 초파리 뇌는 전부 분석했다는 비유도 곁들였습니다.

확인 불가: 기사의 회사·모델 이름·점수 향상 폭은 음성 기록이 불분명하고 이 환경에서 확인하지 못했습니다. 작성자가 아는 범위에서는 모델 내부를 해석하려는 연구 분야(해석가능성)가 있고 작은 모델에서 시도되며, 초파리 뇌 전체의 연결 지도는 2024년에 공개된 것으로 압니다(작성자 지식, 미확인). 수업에서 사실로 전하려면 출처를 먼저 확인하세요. 이 기사가 맞더라도 “큰 상용 모델의 가중치를 사람이 직접 고칠 수 있다”는 뜻은 아닙니다(03절).

강의에서 덧붙인 말 · 채팅 화면은 껍데기, API는 직접 쓰는 통로 강의

강사는 채팅 프로그램을 “누가 만들어 놓은 것이고, AI 자체가 아니라 AI를 쓸 수 있는 껍데기”라고 했습니다. 껍데기 없이 모델을 직접 가져다 쓰려면 API를 씁니다. 같은 모델을 화면으로 쓸 수도, API로 쓸 수도 있다는 점이 p.9–11의 요점입니다.

시연에서는 LM Studio의 로컬 서버 기능을 보여 주었습니다. 내 컴퓨터에 올려 둔 모델에 API 서버를 열어 두면, 채팅창 없이도 다른 프로그램이 필요할 때마다 그 모델을 불러 쓸 수 있습니다. 외부 모델 API를 쓰는 것(p.11)과 같은 구조이고, 모델이 도는 컴퓨터가 내 것이라는 점만 다릅니다.

보충 · 자료 밖 내용 공식 문서 확인

LM Studio 공식 문서 저장소(lmstudio-ai/docs)에 “OpenAI Compatibility Endpoints” 항목이 있어, 로컬 서버가 널리 쓰이는 외부 API와 같은 형식(OpenAI 호환)을 제공함을 확인했습니다. 따라서 같은 프로그램에서 접속 주소만 바꿔 외부 모델과 로컬 모델을 번갈아 시험할 수 있습니다. 지원하는 항목의 범위는 쓰는 버전의 문서에서 확인하세요.

확인 불가 · 구독과 API 크레딧 미확인

강사는 월 100달러 이상 구독하면 같은 금액의 API 크레딧을 받는다고 설명했습니다. 구독 요금제와 API 요금은 서로 다른 상품인 경우가 많고, 이런 혜택이 있는지와 조건은 서비스와 시기에 따라 달라서 제 쪽에서는 확인할 수 없었습니다. 수업에서 그대로 전하지 말고 각 서비스의 공식 안내에서 확인하세요(예: Claude 구독은 support.claude.com, API는 docs.claude.com).

같은 Qwen2.5 계열이라도 0.5B·7B는 Apache 2.0이고 3B·72B는 별도 라이선스입니다. p.14의 “공개되었다고 모든 용도가 허용되지는 않는다”를 보여 주는 실제 사례이고, 07절의 0.5B 모델 카드(Apache 2.0)와도 일치합니다.

“공개 가중치(open weights)”와 “오픈소스”는 같은 말이 아닙니다. 오픈소스 이니셔티브(OSI)가 2024년에 발표한 오픈소스 AI 정의는 가중치뿐 아니라 학습 코드와 학습 자료에 관한 충분한 정보까지 공개되어야 오픈소스 AI로 봅니다(작성자 지식, 원문 미확인). 그래서 가중치만 공개한 모델은 흔히 “공개 가중치 모델”로 따로 부릅니다. 수업에서는 학습자가 “오픈소스니까 마음대로 써도 된다”고 말할 때 이 구분과 라이선스 확인을 함께 짚어 주세요.

검증 · “상용 모델은 튜닝할 방법이 없다” 단순화 가능

상용 모델의 가중치를 내가 내려받아 직접 바꾸는 것은 불가능합니다. 다만 작성자가 알기로는 일부 제공자가 일부 모델에 대해 제공자가 대신 돌려 주는 미세조정 기능을 따로 제공합니다(작성자 지식, 이 환경에서는 확인하지 못함). 그래서 “방법이 전혀 없다”보다 “가중치를 받아 직접 바꿀 수는 없고, 제공자가 허용하는 범위에서만 가능하다”가 정확합니다. 수업에서는 후자로 말하고, 쓰려는 모델의 공식 안내를 확인하게 하세요. 미세조정 자체는 p.94–96에서 다룹니다.

강의에서 덧붙인 말 · OpenRouter 같은 중계 서비스 강의

모델이 너무 많아 하나씩 가입해 쓰기 불편해서, 여러 회사의 모델을 한곳에서 API로 쓰게 해 주는 중계 서비스가 생겼다고 했습니다. 강의에서 보여 준 서비스가 OpenRouter입니다(음성 기록에는 ‘오픈라우터’로 적힘).

  • 공개 모델은 누구나 내려받을 수 있어서, 같은 모델을 서비스하는 제공자(provider)가 세계 곳곳에 여러 곳 있습니다. 같은 모델이라도 제공자마다 가격이 다르므로 가장 싼 곳을 고를 수 있습니다.
  • 크레딧을 충전한 뒤 그 크레딧으로 API를 부르는 방식이고, 채팅 화면도 제공합니다.
  • 강사는 이를 이용해 전 세계 모델을 두루 시험해 보라고 권했습니다.

강의 안의 모순: 어떤 대목에서는 “Claude·GPT 같은 상용 모델은 이런 서비스가 필요 없다”고 했고, 다른 대목에서는 “상용 모델도 목록에 다 있다”고 했습니다. 작성자가 아는 바로는 상용 모델도 중계 서비스에 올라 있으며, 이 경우 제공자는 원래 회사 하나입니다(작성자 지식, 미확인). 공개 모델은 제공자가 여럿, 상용 모델은 원래 회사 하나라고 정리하면 두 말이 모두 맞습니다.

주의 · GB의 두 가지 뜻

자료는 1GB를 10억 바이트로 둡니다. 운영체제나 일부 도구는 1GB를 2³⁰ = 1,073,741,824바이트(정확히는 GiB)로 표시해서, 같은 파일이 약 7% 작은 숫자로 보일 수 있습니다. 학습자가 “계산과 다르다”고 하면 단위부터 확인하세요.

검증 · “PCI 슬롯이 제일 빠르다”는 설명 보완 보완 필요

강사는 윈도우 PC의 그래픽 카드가 가장 빠르다고 했습니다. 방향은 맞지만, 생성 속도를 좌우하는 것은 보통 PCI 슬롯이 아니라 가중치가 올라가 있는 메모리의 대역폭입니다(작성자 지식). 일반적으로 그래픽 카드의 전용 메모리가 가장 빠르고, 통합 메모리 기기는 그보다 느리다고 알려져 있습니다. 대략적인 상한은 이렇게 어림할 수 있습니다.

초당 생성 토큰 수의 상한 ≈ 메모리 대역폭 ÷ 모델 파일 크기 (밀집 모델 기준) 예) 13.5GB(27B·4비트)에서 대역폭 256GB/s → 약 19토큰/초 대역폭 546GB/s → 약 40토큰/초 대역폭 1,000GB/s → 약 74토큰/초

세 대역폭은 설명용 가정값입니다. 이 어림은 상한이고 실제는 더 낮습니다. 작은 모델에서는 아예 맞지 않습니다. 예를 들어 05절에서 본 Qwen2.5-0.5B 공식 측정은 대역폭이 매우 큰 A100에서도 Transformers로는 초당 47토큰에 그쳤고, 같은 모델을 vLLM으로 돌린 측정은 초당 311.55토큰이었습니다. 모델이 작으면 모델 파일을 읽는 시간이 아니라 실행 프로그램의 처리 지연 같은 다른 요인이 속도를 정하기 때문입니다. 전문가 혼합(MoE) 모델은 한 번에 일부 매개변수만 읽어서 다시 다릅니다.

검증 · 필요한 메모리는 파일 크기보다 크다

05절의 공식 측정에서 0.5B 모델은 입력이 거의 없을 때 0.97GB였지만 입력이 30,720토큰이면 2.34GB로 늘었습니다(+1.37GB). 모델 파일이 메모리에 들어간다고 끝이 아니라, 문맥 길이만큼 더 필요하고 운영체제와 다른 프로그램의 몫도 남겨야 합니다. 강사가 “32GB급 모델을 48GB 맥에서 돌리면 다른 게 버벅거렸다”고 한 경험과 맞는 설명입니다. 또 맥은 통합 메모리 중 GPU가 쓸 수 있는 비율에 기본 상한이 있는 것으로 알려져 있습니다(작성자 지식, 대략 3분의 2~4분의 3으로 기억하며 미확인). 정확한 값은 사용할 기기와 도구의 안내를 확인하세요.

강의 포인트 · 내 PC로 돌릴 수 있는지 확인하는 순서

  1. 모델 파일 크기를 확인한다 (또는 매개변수 수 × 비트 수 ÷ 8로 어림한다).
  2. 내 메모리(그래픽 메모리 또는 통합 메모리)가 파일 크기 + 문맥·운영체제 몫의 여유를 감당하는지 본다.
  3. 돌아가더라도 속도는 메모리 대역폭에 달려 있음을 안내한다.
  4. 모델 카드에서 라이선스와 허용 용도를 확인한다 (03절).
  5. 시험에는 공개용 예제만 쓴다. 내 PC에서 돌려도 외부 검색 같은 도구를 연결하면 자료가 밖으로 나갈 수 있다(p.99).

주의 · 정렬을 줄인 파생 모델

강사는 모델 이름 뒤에 ‘uncensored’가 붙은 파생 모델을 소개하며, 모델이 불법적인 일을 중간에 막지 못하도록 풀어 놓은 버전이라고 설명했습니다. 1일차의 정렬(p.100)을 약하게 만든 모델이라는 뜻입니다. 쓰는 사람이 책임져야 하는 영역이 커지므로, 라이선스·기관 규정·법적 책임을 먼저 확인해야 하고 수업 시연용으로는 권하지 않습니다. 강사는 또 중국 모델의 API가 한국사 문제에서 중단되는 경험을 했다고 했는데, 이는 모델이 아니라 제공자 쪽 필터일 수 있으며 원인은 확인할 수 없었습니다.

  • MMLU는 Hendrycks 등(2021, ICLR)이 제안한 평가로, 57개 과제의 객관식 문제로 이루어져 있습니다(p.45와 일치).

그래서 p.48의 결론처럼, 공개 점수는 후보를 좁히는 데 쓰고, 최종 선택은 내 자료로 직접 시험한 결과로 합니다.

  • 종합 지능 지수. 강사는 AI의 지능을 수치로 측정해 보여 주는 지표(음성 기록에는 ‘AI 인텔리전스 인덱스’)를 소개하고 “IQ를 측정한 것”에 비유했습니다. 모델마다 점수가 있고, 이 지수는 최근 기준이 바뀌어 수치가 달라졌다고 했습니다. 판본이 다른 점수는 직접 비교할 수 없다는 p.44·p.47의 원칙과 같습니다.
  • 가격–지능 그래프. 가로는 가격, 세로는 지능입니다. 가격이 낮고 지능이 높은 쪽이 좋습니다. 그래프의 점선은 “같은 가격에서 가장 높은 지능의 모델을 이은 선”이고, 이 선 위의 모델은 “그 가격대에서는 지능 기준으로 가장 좋다”는 뜻입니다.
  • 그 밖의 순위. 문제 해결에 쓴 토큰량(적을수록 좋음), 비용, 출력 속도가 따로 있고, 공개 가중치·멀티모달·국가별로 거를 수 있습니다. 세부 지표로는 지식 노동 종합, 에이전트, 코딩 등이 있다고 했습니다.
  • 숫자 하나의 한계. 지능을 숫자 하나로 표현하면 너무 거칠므로 세부 지표를 하나씩 공부하라고 했습니다. 기업은 자기 모델이 잘 나온 지표를 골라 자랑하므로, 어디에 약한가도 함께 봐야 합니다. 모델 발표 자료의 지표 표를 캡처해 두고 무엇을 측정하는지 공부하라고도 했습니다.

13핵심 정리

  • 모델을 쓰려면 가중치 + 실행 프로그램 + 컴퓨터가 필요하고, 내려받기와 실행은 다른 일입니다.
  • 공개 여부, 실행 주체, 이용 통로, 허용 용도는 서로 다른 질문입니다. 같은 계열 모델도 라이선스가 다를 수 있습니다.
  • 저장량은 수치 개수 × 값 하나의 바이트 수로 어림할 수 있고, 실제 메모리는 입력 길이에 따라 더 늘어납니다.
  • 모델 카드는 개별 판본의 값을 읽고, 벤치마크 점수는 과제·설정·판본과 함께 읽습니다.
  • 모델의 제안과 설명은 실행의 증거가 아닙니다. 실행은 도구 기록으로 확인합니다.
  • 내 PC에서 돌릴 때는 모델 파일 크기 + 여유 메모리부터 확인하고, 속도는 메모리 대역폭이 좌우합니다.
  • 공개 점수와 점선(가격–지능)은 후보를 좁히는 용도이고, 최종 선택은 내 과제에서 직접 써 본 결과로 합니다.
